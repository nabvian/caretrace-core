# UI harness

Renders every CARETRACE screen in a simulated DOM and reports what each one
actually produced. `node --check` proves a file parses; this proves a screen
runs.

## Why it exists

The defects this layer produces are runtime, not syntactic: a view-map entry
that was never registered, a helper that does not exist, an API field that was
renamed. Each of those parses cleanly and renders a broken screen.

## Setup

```bash
cd uiharness
npm install jsdom          # add --cache "$PWD/.npmcache" if npm's cache is unwritable
```

## Use

```bash
python uiharness/snapshot_api.py    # refresh captured API responses
cd uiharness
node render_screens.js              # every screen
node render_screens.js codings --dump   # one screen, with its rendered text
```

`pytest tests/test_web_screens.py` does both steps and skips cleanly when Node
or jsdom is absent.

## Fixtures

`fixtures/api.json` is generated by `snapshot_api.py`, which drives the real
FastAPI app in-process. Never hand-edit it: if a response shape changes,
re-run the snapshot.

`SKIP` means a screen could not be exercised here — the evidence graph draws to
canvas, which jsdom does not implement. It is never counted as a pass.
